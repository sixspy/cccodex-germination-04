# 发芽口径核算台

种子检验室按书面口径给批次出数。现行口径的分母是播种粒数减去霉粒数，分子是发芽粒数。旧口径把霉粒留在分母里。核算员可以按现行口径再出一版，旧版数字仍留在记录里。

出数之后，分母还要落进作物库。落库前先定**今日分口**，只准定一种：

- **通栏**：全室收成合成一条宽行推进作物库；
- **分作物**：按作物分行落入作物库。

分口交给后台收口，规矩如下：

- 构建走法与今日分口不一致 → 截住，页面回「分口落法偏了」，并记一笔走偏；
- 作物名空缺 → 不准出数（通栏整笔截住，分作物列为未齐）；
- 通栏下任何作物缺现行分母 → 整笔截住；
- 分作物下齐备作物先落，未齐作物名列在预看；
- 两组同时抢出数 → 只保留先手（同日同口唯一约束），后手整笔退回并记一笔争用。

核算台同屏办完：作物列表（现行回数、分口回数、分口名同排对读）、分母详情（可翻开床次、出数记录、分口走偏与争用）、预看（贴在分母详情旁，只看不落库）、分口策略、混口队列、今日落库（可拆开看通栏与分作物）。

## 技术栈

| 层 | 选型 |
|----|------|
| 接口 | Python Bottle + Waitress |
| 页面 | Svelte 4，无组件库 |
| 数据库 | PostgreSQL 16 |

| 服务 | 地址 |

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/board` | 核算台一整屏：分口、作物列表、批次分母、今日落库、走偏与争用 |
| POST | `/api/split` | 定今日分口 `{mode: "aggregate" \| "per_crop"}`，只准定一种 |
| POST | `/api/library/preview` | 预看 `{mode, crops}`：可落的行、未齐作物、走偏与争用预警，不写库 |
| POST | `/api/library/publish` | 落库 `{mode, crops}`：走偏 409、整笔截住 400、争用 409 只保留先手 |
| GET | `/api/trials` · `/api/trials/<id>` | 批次列表与详情 |
| POST | `/api/trials/<id>/publish` | 按现行口径给单个批次出数 |

「今日」按数据库服务器日期（`CURRENT_DATE`）划线。
